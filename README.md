# Red Garden GitHub Pages 前端

这是手机和电脑共用的静态前端。它不包含 R2 密钥、123 会话或主题文件。

## 开发与发布

前端使用 Vite + React，界面组件使用 Tailwind CSS 和 shadcn/ui。React 布局在 `site/shell.jsx`，设备端处理和既有 API 交互在 `site/app.js`。

- 本地：`npm ci`，然后运行 `npm run dev`。若要连接共享库，在「存储设置 → 多设备访问」填写同步地址。
- GitHub Pages：`npm run build` 生成 `dist/`。仓库的 Pages Source 选择 **GitHub Actions**，推送 `main` 后自动发布。
- Cloudflare Pages：`npm run build:pages` 生成含 Worker 的 `dist-pages/`。沿用项目 `red-garden-sync` 与现有 R2 绑定。部署前运行 `npm run verify -- --cloudflare`，部署后用 `npm run verify -- --cloudflare --url=https://red-garden-sync.pages.dev --require-current` 核对线上文件。
- Android：新版优先加载线上前端，联网失败时回退内置 `dist/`。旧 APK 需要升级一次才能获得这一行为。

Pages 版本自动使用共享同步地址，所有设备需要私有库访问口令，前端不需要 R2 Access Key。地址和 Token 修改后自动保存在当前设备；换电脑可在「存储设置 → 迁移设备配置」导出加密配置，用同一口令在另一台电脑导入。123 会话可选择一起迁移，账号密码不会保存或导出。

资源索引缓存在设备的 IndexedDB，重开页面优先显示缓存，不重新读取整库；其他设备修改后点击刷新获取。空闲任务停止轮询；启用自动继续时，旧的任务快照仍会做一次检查。云端共享清单使用 R2 条件写入：首次迁移只读记录 JSON，后续手动刷新读取一份清单并支持 ETag / 304；改名称、分类或标签不扫描对象列表，同一记录过期修改返回 409。旧缓存首次编辑会先补齐记录引用。缓存不是备份，清除浏览器数据后会重新读取。

三个库支持最新入库、最早入库、最近修改、名称、大小排序和最近 24 小时筛选；支持批量添加、移除、替换标签，以及根据已有分类和文件类型补标签。上传前检查写入权限，整批结束显示汇总，失败文件留在待上传列表。

导入页支持 ZIP：在本机提取子文件夹里的 `.red/.ttf/.otf/.woff/.woff2/.svg/.html/.htm`，进入原有确认、压缩、查重和上传流程，ZIP 本身不上传。忽略无关文件，不递归嵌套 ZIP；加密和 ZIP64 不支持。限制单个 ZIP 256 MiB、单个提取文件 96 MiB、最多 200 个匹配文件、解压合计 512 MiB；拒绝危险路径并校验大小与 CRC。

在填写同步 Worker 地址后，页面会切换到免费浏览器本地模式：普通 RED 在当前手机/电脑读取、图片压缩、重新封包并生成书架+书封预览；字体按 SHA-256 查重后上传原字体文件，并在导入时渲染字形做自动分类、生成样张图，卡片始终有可见预览；SVG/HTML 收藏也按 SHA-256 去重，SVG 生成缩略图，HTML 用无权限 sandbox 预览，并可按作者、风格和标签分类。主题可按作者筛选，三个库都支持批量删除和「下载所选」（打包成 ZIP）。批量下载由共享 Worker 的 `/api/download` 直接从 R2 流式打包：ZIP 使用 Stored 条目，不对已经压缩过的字体和 RED 包做第二次 DEFLATE，浏览器只发起一次原生下载、可在下载列表查看进度，也不会把几十 MB 文件读进 JS 内存；包内附 `manifest.json`，个别 R2 对象缺失时会写入 `__errors.json` 而不是让整个下载失败。未连接同步 API 时保留浏览器本地打包兜底。

加密 RED v2 只把 4–5 KB 的「文件头 + 加密清单」发给 Worker 的 `/api/private/directory` 解析资源目录，图片字节始终留在设备里；压缩后由 `/api/private/seal` 只重封文件头，设备本地拼装完整包。CPU 密集的 ZIP 解析、图片解码与 WebP 编码在 `free_codec_worker.js` 的 Web Worker 池里并发执行，不再阻塞界面。旧版 Worker 不存在这些接口时会自动回退到整包 `/api/private/repack`。

上传成功后会弹出「删除本地文件」对话框：列出这一批真正写进 R2 的文件，默认全选，可以逐项取消或整批保留。手机上由 APK 的原生桥用系统 Storage Access Framework 删除（系统可能再确认一次）；桌面 Chrome/Edge 在勾选导入页的「清理本地文件」后，「选择文件夹」改走 File System Access 的读写目录句柄，删的是目录里那份真实文件。用「选择文件」、拖拽或在普通手机浏览器里上传时，网页没有删除本机文件的权限，此时不会弹出一个按不动的删除框，而是提示需要手动清理。

上传进度写入共享 R2 的持久化任务，刷新页面或换一台设备都能看到；勾选导入页的「后台暂存」会先把原文件上传到 R2 `staging/`，之后在启用自动继续的设备接着处理。处理完成后删除暂存原文件。服务器/命令行入口为 `scripts/remote-import.mjs`，写入 Token 从环境变量提供。

123 登录、扫码轮询和会话验证由设备直连 123，不再在网络失败时自动换成 Worker 出口。密码仅用于本次请求；会话 Token 保存在设备，失败不会清空旧会话。支持返回码 0/200 和从后台切回后恢复扫码，保留平台返回的验证提示，区分网络、超时和登录拒绝。会话测试只读取账户信息，备份清单和原包备份仍走现有 Worker 接口；平台风控和真实账号登录需要本人验证。旧 Worker 登录代理保留兼容旧客户端，新前端不调用它。

要确认「真的有备份」：点「查看备份清单」会列出备份目录内的文件（名称、大小、文件数、合计字节），并与共享库里的主题记录对账，显示已备份 / 失败 / 未备份数量；主题卡片也会显示「123 已备份」「123 未备份」或「123 备份失败」徽标。清单与对账都是只读的。备份只在「导入 .red → 确认并压缩保存」时发生，字体、SVG/HTML、预览图不写入 123。若想单独验证写入链路，点「验证备份写入」会在备份目录下新建 `_verify/` 子目录并上传一个固定内容的小 `.red` 测试文件（会保留在云盘），成功后显示文件路径、大小和 FileId；重复点击会复用同一文件，不会重复占用空间。

免费模式的压缩仍由浏览器执行：Cloudflare Workers 免费运行时没有画布（`createImageBitmap` / `OffscreenCanvas`），CPU 也只有 10ms，所以图片重压缩不可能搬到云端。队列本身在 R2，关掉页面不会丢，换设备或重开页面会自动继续；其中一条 `running` 任务若因关页中断，会在空闲两分钟后被下一台打开的设备接管，避免两台设备同时处理同一批。

压缩方案有三档，导入页「RED 图片压缩」里可选：「最高性价比」保留原尺寸、94% 画质 WebP；「最大压缩」把底栏限制到 384 px、启动图、阅读背景与书架底 2560 px、其余静态图 1600 px，用 90% 画质 WebP，并让底栏在无损与有损结果里取更小的一张；「自选模式」完全自己定：静态图编码可选高画质 WebP（画质滑杆 50–100，带 −/+ 微调）或无损 PNG（只按长边上限等比缩小、不改像素），长边上限可选保持原尺寸 / 2560 / 1920 / 1600 / 1280 / 1024，GIF 可选仅无损重编码或量化到 256/128/64 色，另外可以关掉「同时压缩阅读背景」和底栏的无损比较。改完参数，预计体积区间会按你选的参数重算。PNG/JPEG 现在会真正转成 WebP（早期版本因为编码入口判断写错，大图其实只是被重新编码成原格式，整包只省三成左右；修正后 PNG/JPEG 主题通常能省 70%–90%）。无损 PNG 只减少尺寸、不改善编码效率：照片类素材重新编码成 PNG 往往比原图还大，这时会保留原字节并记为「压缩结果未变小」，自选模式下 20 张图通常只有 3–4 张能靠缩边真正变小。动图 GIF 用 `omggif` 重新量化：保留尺寸、帧数、延时与 disposal，只把颜色合并到 64/96/128 色，重新编码不比原来小时保留原字节；动画 WebP、APNG 和九宫格资源仍原样保留。勾选主题后，导入页会按包里静态图和动图各占多少给出预计大小区间。

## 免费 Worker

`pages/worker-api.js`（由 `pages/_worker.js` 挂载，R2 绑定 `R2_ASSETS`）是 Cloudflare Pages 正在使用的同步接口；`worker/worker.js` 是同一实现的可单独部署入口（R2 绑定 `ASSETS`）。接口包含内容寻址对象读写、共享对象安全的删除（`DELETE /api/objects/staging/<sha>.<ext>` 只允许删暂存副本，库内对象走记录删除）、分类更新、持久化任务（`/api/jobs`）、加密目录 `/api/private/directory`、前缀重封 `/api/private/seal`、兼容旧客户端的 `/api/private/repack`，网页端 123 登录代理 `/api/storage/123/login`、可选的原包备份 `/api/backup/123`、只读连接校验 `/api/backup/123/verify`、只读备份清单 `/api/backup/123/list`，以及流式批量下载 `/api/download?kind=font&ids=...`（`&probe=1` 只返回文件清单，不读取对象字节）。Worker 不持有 123 会话，浏览器也拿不到服务端私有格式密钥。

R2 对象键只保留可读名：`compressed/少女心事-压缩.red`、`originals/少女心事-原包.red`、`previews/少女心事-预览.jpg`、`fonts/浪漫融化在银河里.ttf`。SHA-256 不再写进文件名——浏览器上传时通过 `X-Content-SHA256` 请求头声明，Worker 校验一致后写进对象自定义元数据 `sha256`。同名但内容不同时自动加 `-2`、`-3`，内容相同则复用同一个对象。**改动前写入的对象仍带 `~<sha>` 后缀，接口继续可读可删，不迁移也能正常使用**；重新上传一次即可换成干净名字。

不要将 `SYNC_WRITE_TOKEN`、R2 Access Key、Secret Access Key、`REEDEN_SECRET_KEY` 或 123 会话提交到 GitHub。

## 界面

主题库、字体库、收藏库共用暖白底、墨色文字和鼠尾草绿强调，用细线分层。支持键盘 `/` 或 `Ctrl+K` 搜索、清空筛选和分页。

- **主题库**：图片左下角显示作者，下方只显示主题名与类别；搜索同时匹配名称、作者、标签和源文件名。普通点击卡片打开详情，在详情里点击图片才放大。勾选第一项或点「多选」后，卡片整块用于选择；右上角 `⋯` 仍可查看详情。手机默认双列网格，也可切换列表。
- **详情**：预览、压缩结果和下载操作优先显示，名称作者、分类标签和文件维护折叠收起。点击弹窗外可关闭；保存完成不会重新打开已关闭的详情。「文件信息与维护 → 更新预览」可手动重建旧图，轮播区域高 400 / 1000 画布；只在点击时读取主题，不在启动时批量重建。
- **收藏库与手机端**：收藏支持批量下载、删除和标签编辑。手机顶栏固定，有选中项时显示批量操作。布局经 1440、768、390px 浏览器检查。

## Android APK

`android/` 是一个轻量 WebView 壳：它把同一份 Pages 前端打进 APK，并保留 GitHub Pages origin，因此手机和电脑填写同一个 R2 Worker 后共用同一套主题、字体和预览库。APK 需要联网访问 R2；它不会把 R2 密钥或 123 会话打包进去。文件选择器使用 `ACTION_OPEN_DOCUMENT` 并申请写权限，因此「上传成功后删除本地文件」只能删本次通过应用选择的文件，按显示名与大小匹配；网页层只在本站点 origin 下拿得到 `RedGardenNative` 桥。

没有 Android Studio 时也可以在 Windows Git Bash 中用 `android/build-apk.sh` 手动打包：脚本使用 `android/toolchain/` 下的 JDK 17、build-tools 35 和 platform 35，依次跑 aapt2 → javac → d8 → zipalign → apksigner，产出 `android/build/red-garden-1.2.0.apk`，依赖本机 `android/manual-build/debug.keystore`。脚本自动定位仓库，和 Gradle 共用 `android/version.properties`。两条安装渠道保留各自原有包名与签名，避免覆盖已有安装；跨渠道不能保证直接覆盖升级。工具链、构建目录和签名文件不要提交。

推送仓库后，在 GitHub Actions 运行 **Build Red Garden Android APK**，下载构建产物 `red-garden-android-debug` 里的 `app-debug.apk`。这是 debug 签名包，适合个人安装；如果公开分发，需要换成自己的 release keystore。

## 私有库、配置与恢复

默认启用私有读取。`SYNC_WRITE_TOKEN` 同时用于读取和写入；`PRIVATE_LIBRARY=false` 仅用于有意公开的资源库。预览与下载使用短期签名地址，口令不放入资源 URL。不要给 R2 桶启用公开域名。私有模式不依赖 Supabase。

新设备：在已连接设备的「存储设置 → 多设备访问」生成接入链接，另一台设备打开并输入迁移口令。也可导出 / 导入加密配置。AES-GCM 密文可以保存到私有库，迁移口令始终留在设备，链接与口令请分开传送。123 会话可选包含在密文里，平台会话过期仍须本人重新验证。

普通导入先把 File 与可持久化的文件句柄保存在 IndexedDB，页面顶部显示「继续上传」。逐文件成功后移除恢复副本；失败及尚未确认的文件保留。跨电脑接续需要先勾选「后台暂存」，或用 CLI 先上传原文件；逐文件接续，不是字节级断点上传。浏览器存储空间不足会明确报错，清除站点数据会移除本机恢复副本。

CLI 先建任务、再逐项上传并登记。中断后重新选择同一批文件，追加 `--resume <任务ID>`；已暂存文件通过 HEAD + SHA-256 检查后跳过。123 备份失败会记录错误，不中止 R2 入库。网页处理中的批次有两分钟租约，其他设备等待租约到期后可接管。

删除资源先更新共享清单，文件进入待清理列表。存储设置中「历史文件清理」先生成核对清单，再由用户确认删除；只处理无引用且满 7 天的旧文件，每批最多 50 个。未入库原文件默认保留。清理前核对清单版本与对象 ETag，执行期间暂停新写入。没有自动扫描删除真实历史文件。

本地清理需主动开启。文件句柄不能删除时可另行授权所在文件夹，仅匹配内容一致的唯一文件；删除前再次核对 SHA-256。权限不足、文件变化或系统未确认的结果会明确显示，不能再把未执行的删除当成功。

## 构建依赖与验证

`npm ci` 的 postinstall 会暂时禁用 picomatch 重复 extglob（`+(...)` / `*(...)`），降低已知构建期正则回溯风险；普通 `**/*.js` 不受影响。上游未提供完整修复时 `npm audit` 的版本警告仍会保留，本地缓解不等于上游已修复。生产依赖审计通过。

验证：`node worker/test-worker.mjs`、`node worker/test-private-repack.mjs`、`node scripts/test-library-maintenance.mjs`、`node scripts/test-sync-resume.mjs`、`node scripts/test-compress-references.mjs`；构建后运行 `node scripts/verify-pages.mjs --cloudflare`。新增测试覆盖私有读取、签名资源、并发 CAS、304、核对清理、租约、CLI 中断恢复和构建 glob 缓解。

## RED 下载与批量处理

RED 下载统一命名为「作者 - 主题名.red」，不重复作者前缀并保留标题中的版本号。主题库批量下载默认只包含压缩 RED；勾选「附带原包与预览」才加入这些附件。直接下载支持 Content-Length、ETag / 304、Range / If-Range；ZIP 按数据块输出，私有下载使用签名链接，不再先发一次探测请求。

批量 RED 处理复用识别时的预览，不把全部原包同时留在待处理数组中；压缩、原包上传、压缩包与预览上传并行执行。按设备能力限制工作线程，并将上传请求限制为最多四个；新文件不再逐个多发 HEAD，失败重试仍会检查已上传内容。相同原始 SHA-256 的已入库主题跳过解包和重压缩。

待处理区支持「选中重复」和「移除所选」：主题按 SHA-256 区分完全相同与仅同名作者，字体 / SVG / HTML 按 SHA-256 检查；同批重复保留第一份。移除时默认保留本地文件，可勾选继续核对本地原件，再按文件句柄或授权文件夹删除。仅同名作者可能是不同版本，不能当作相同内容自动删除。ZIP 原包不自动删除。

回归补充：`node scripts/test-transfer-performance.mjs` 验证作者文件名、签名下载、断点与缓存、ZIP 实际内容、默认附件范围及流式读取。
